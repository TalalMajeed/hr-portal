# DU Job Portal

A web portal for Daanish University (DU) that runs every hire, faculty and administrative, from the approved position to the Selection Board report.

The full requirements are in [SRS.pdf](SRS.pdf). The look follows [THEME.md](THEME.md), taken from du.edu.pk.

## What it covers

Each position moves through ten stages:

1. Position and ToRs: request, budget, approval
2. Job description: criteria and required documents
3. Advertisement: careers page, exported ads, agencies
4. Applications: online form and uploads
5. Shortlisting: screening and expert scores
6. Interview panel: invitations and availability
7. Interview: slots, confirmation, video link
8. Faculty talk or second round
9. Evaluation: scores and panel consensus
10. Selection Board: pack, recommendation, offer

Roles: super admin, Executive Director, HR officer, hiring lead, shortlisting reviewer, panel member, Selection Board member, headhunter or agency, and candidate. External reviewers and panelists work through secure links without full accounts.

Out of scope for now: payroll, onboarding after an offer is accepted, and student admissions.

## Getting started

Requires Node.js 20 or later and a Postgres database (the project uses Neon).

```bash
cd portal
npm install
cp .env.example .env.local   # then fill in DATABASE_URL and DATABASE_URL_UNPOOLED
npm run db:migrate           # create the tables
npm run db:bootstrap         # templates, settings and the first super admin (needs ADMIN_* vars)
npm run dev
```

Open http://localhost:3000. For a local Postgres, set `DATABASE_URL=postgresql://<you>@localhost:5432/du_portal`; otherwise use the Neon `dev` branch. Production uses Neon `main`.

For test accounts in every role, run `npm run db:seed:dev` on a local database. The accounts and their password are listed in CLAUDE.md.

### Database changes

The schema lives in `portal/src/lib/db/schema.ts` and is managed by Drizzle Kit. Every change goes through a migration in `portal/migrations/`:

1. Edit `schema.ts`.
2. `npm run db:generate` writes a new SQL file into `migrations/`. Read it.
3. `npm run db:migrate` applies it to your database.
4. Commit the schema change and the migration together. Production deploys apply pending migrations before building.

For changes Drizzle can't express (triggers, data fixes), use `npx drizzle-kit generate --custom --name <what>` and write the SQL by hand. Never edit an applied migration.

### Email

Every email is kept in the portal record (HR sees them under Emails, candidates under Messages). Set `RESEND_API_KEY` and `MAIL_FROM` to deliver them. Until then, the sign-up page shows the verification link so candidates can activate their accounts, and two-step sign-in stays off.

## Repository layout

```
hr-portal/
├── SRS.pdf          Software requirements specification
├── README.md
├── THEME.md         DU colours, fonts and components
├── CLAUDE.md        Notes for Claude Code
└── portal/          Next.js app (front end, server actions and API routes)
    ├── src/app/         Routes: (public) careers and sign-in, (portal) signed-in areas, print, api
    ├── src/actions/     Server actions, one file per area
    ├── src/components/  Every component: ui primitives, layout, and one folder per area
    ├── src/lib/         Database, auth, email, uploads, reports and domain logic
    ├── migrations/      SQL migrations, generated by Drizzle Kit
    └── scripts/         First-run bootstrap and default templates
```

## Stack

- Next.js 16 (App Router, server actions) with React 19 and TypeScript
- Tailwind CSS 4
- Postgres (Neon) through Drizzle ORM and node-postgres, with Drizzle Kit migrations
- bcrypt password hashing, zod validation, ExcelJS for exports, Lucide icons

## Scripts

Run these from `portal/`:

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the dev server |
| `npm run db:generate` | Write a migration for schema changes |
| `npm run db:migrate` | Apply pending migrations |
| `npm run db:bootstrap` | Add templates, settings and the first super admin |
| `npm run db:seed:dev` | Development accounts for every role (local databases only) |
| `npm run db:studio` | Browse the database |
| `npm run build` | Build for production |
| `npm run start` | Serve the production build |
| `npm run lint` | Lint the code |
| `npm run typecheck` | Check types |

## Integrations

| Integration | In this build |
| --- | --- |
| Zoom | Real meetings with the waiting room on when `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID` and `ZOOM_CLIENT_SECRET` are set; otherwise simulated links. Meet and Teams are simulated. |
| Calendar | Confirmed sessions download as `.ics` invites for Google Calendar and Outlook, updated on reschedule. |
| Email | Stored in the portal; delivered through Resend when `RESEND_API_KEY` is set. |
| Reminders | Vercel Cron calls `/api/cron/reminders` daily (the Hobby plan limit), and opening the day schedule also sends due reminders. Protected by `CRON_SECRET`. |
| Data import | CSV import of existing candidates under Import. |
| Single sign-on, SMS and WhatsApp | Not in this build. |
